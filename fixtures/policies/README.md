# Local S14 contract review bundle

Run `node scripts/test-s14.mjs` from the repository root. `scripts/check-s14.mjs PATH` independently parses and checks one report without invoking Rust or regenerating the candidate. The runner checks seven positive producer reports (complete, partial, omitted, explicit intent, resolved, blocked target and reordered links), six full-policy byte/digest vectors, scope/manifest identity vectors, lifecycle decisions and committed negative mutations. The ignored Rust `export_candidate_fixture` test regenerates report fixtures; it is not needed to run the JavaScript checker.

The full-policy vector `volatile_ids_unchanged` supplies different run, website, binding and timing inputs while keeping policy bytes equal. Website and binding still affect the separate scope digest and must be authenticated independently. Manifest digest excludes run-specific populations, which the validator separately verifies. Edge ordinals are report-local and cannot resolve across runs. The finite local contract and state matrix are frozen as `s14-local-1` following independent reviews of producer/checker head `448baa3`; this freeze covers local one-shot output and the committed checker and vectors only. Neither local acceptance nor H01's schema-3 rejection demonstrates receiver support or H04 readiness.

`seed-url-vectors.json` records canonical seed examples. The negative runner includes schema/type coercion, self provenance, malformed URLs and invalid unknown-reason counts. The checker rejects zero-count unknown reasons; producers omit them.

Policy canonical JSON has a lexical integer encoding: base-10, no fraction or exponent. Outside those canonical policy bytes, the Node checker treats report numeric values semantically: integral JSON tokens such as `200`, `200.0`, and `200e0` may parse to the same value, while Rust typed deserialization may reject fractional or exponent spellings for integer fields. The local freeze does not claim raw lexical parity between the two parsers.
