# S14 finding-coverage producer fixtures (schema 4, local only)

Status: **proposed-local-only-not-frozen**. These are synthetic producer fixtures
for the schema-4 `finding_coverage` extension. They are a producer *claim*; the
receiver is the independent verifier. No historical fixture or manifest was
changed; this directory is purely additive.

## Wire shape (version 1)

```json
"finding_coverage": {
  "version": 1,
  "audit": "complete" | "partial",
  "checks": [ {"rule_id": "<pinned rule id>", "status": "complete" | "unknown"} ]
}
```

- `checks` enumerates the full pinned catalogue (`audit::rules()` union the
  policy catalog rule ids), unique and sorted. See `catalogue-v1.json`.
- Absent extension, absent check, or unverified evidence means **unknown**, never
  clean. A positive finding stays visible regardless of coverage.
- `audit: complete` requires every catalogue check `complete` and an independent
  full expected audit + policy finding population equality (including
  multiplicity) on the receiver. The producer's claim does not become a verified
  result until the receiver recomputes it.
- `audit: complete` does **not** mean "no findings". A complete check may contain
  expected findings; `complete-clean-h1` is clean only for `missing_h1`.

## Cases

| File | audit | checks | `missing_h1` finding | Purpose |
| --- | --- | --- | --- | --- |
| `complete-missing-h1.json` | complete | all 88 complete | yes | Complete audit with an observed finding. |
| `complete-clean-h1.json` | complete | all 88 complete | no | Complete audit clean for `missing_h1`; other expected findings remain. |
| `partial-missing-h1.json` | partial | all 88 unknown | yes | Honest unknown (truncated seed, crawl incomplete) that still shows the observed finding; absence is unknown. |
| `partial-clean-h1.json` | partial | 63 complete / 25 unknown | no | Globally partial (one unobserved external edge) with a verified-clean item-local check. |

## Reproducibility

`manifest.json` pins byte length and SHA-256 plus the mutation recipe. The base
is `fixtures/policies/v3-local-complete.json` (SHA-256 in the manifest). The
bytes are generated by actually running `audit::analyze` and the policy pipeline,
then adding the extension; the library unit test
`finding_coverage_prototype::tests::committed_fixtures_are_reproducible`
regenerates and byte-compares every file.

Regenerate (offline, locked, one job):

```sh
cargo run --offline --locked -j1 --features policy-wire-prototype \
  --example make_finding_coverage -- fixtures/contracts/s14-finding-coverage-v1
```

## Bounds and limits

Coverage is relative to retained pages. The extension is an unauthenticated
producer assertion verified only by recomputation; it establishes nothing about
unobserved pages, true server responses, extraction accuracy, authenticity,
sitemap completeness, authorization or production emission. A receiver that
lacks a reconstruction for a catalogue rule must leave that check unknown and
must not accept `audit:complete`.

Deliberate safe-direction limits of this narrow generator (documented, not
bugs):

- Graph targets must be an observed **2xx HTML** non-resource page
  (`page_target_observed`). A link to an observed 404 response or to an observed
  non-HTML internal asset therefore leaves every graph rule unknown, including
  `broken_internal_link`, even though the retained response is fully observed.
  This never fabricates completeness, but it means this generator cannot emit
  "complete with a known broken-link finding". One inadequate page also makes
  the affected rule unknown for every page, because wire v1 is report-wide per
  rule.
- Item-local prerequisites require every retained non-resource page to be
  observed and every 2xx HTML page to be untruncated. Non-HTML and non-2xx
  responses are observed but are not evaluated by the item-local HTML rules, so
  they do not themselves withhold the item-local claim.
- Policy coverage must account for **every** coverage row for a rule. A rule such
  as `noindex` or `http_redirect` has an `observation` row and a
  `policy_violation` row; an omission in either row forces the rule unknown.
- Sitemap and robots checks are complete only relative to the retained per-page
  `in_sitemap` and robots flags; there is no retained evidence of the sitemap or
  `robots.txt` fetch itself.
