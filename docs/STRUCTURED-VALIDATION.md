# Experimental structured-data validation

The `structured_validation` library module is local-only. `seosmith validate-structured REPORT.json` validates an existing saved crawl report without submitting a job or writing to the delivery queue. It produces a standalone wrapper with validation observations and rejects other experimental contract modes. Live crawl integration awaits a durable local-only job mode. It does not alter schema 1/2/3 receipts. Its profile `google-subset-2026-11-21.4` is a deliberately incomplete set of checks, not a comprehensive vocabulary or provider validator. Observations carry a category, code, retained value where available, and an RFC 6901 pointer relative to the page's `structured_data` array; missing-property pointers describe the expected location. Values larger than 4 KiB are omitted and must be read from the source pointer. Output is capped at 512 observations and 512 KiB per page, with an explicit coverage marker when the cap is reached. The caller must retain the original page and block as provenance.

The subset recognizes Product, Article/NewsArticle/BlogPosting, BreadcrumbList, LocalBusiness and selected LocalBusiness subtypes (Restaurant, Store and Pharmacy), and selected text value shapes, missing fields, local JSON-LD references, nested Offer/AggregateOffer requirements and breadcrumb positions. A local Offer reference resolves only when one retained definition exists; ambiguous, external, or missing definitions remain unknown. Unique local address and price specification references resolve to retained definitions; ambiguous or missing definitions remain unknown. A typed node carrying a local `@id` (or extracted microdata `id`) is completed from a single separate untyped retained definition with the same identifier; the node's own properties take precedence, completed values keep the definition's actual occurrence pointer, and ambiguous, symmetric, foreign or missing definitions are never merged. A second typed entry sharing the identifier is a duplicate or conflicting declaration, reported as ambiguous coverage rather than merged. This is a bounded completion of locally identifiable nodes, not full JSON-LD expansion. JSON syntax errors come from existing extraction. It accepts extracted microdata shape, but does not perform JSON-LD expansion, context resolution, subclass inference, or full schema.org validation. Remote contexts and referenced resources are never fetched by this module. The separate resource lookup includes image URLs and ImageObject URLs, and reports only status already present in crawl observations; absence and blocked/error observations remain unknown. Rendered content and business facts are unavailable: visible-content alignment always requires human review. A headline differing from retained source headings is only a review candidate, not evidence that it is invisible. A clean result does not establish eligibility or guarantee a rich result. Truncation is explicitly reported; absent evidence on partial extraction must not be treated as conclusive.

Profiles are based on Google's [Product snippet](https://developers.google.com/search/docs/appearance/structured-data/product-snippet), [Article](https://developers.google.com/search/docs/appearance/structured-data/article), [Breadcrumb](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb), and [Local Business](https://developers.google.com/search/docs/appearance/structured-data/local-business) documentation, reviewed 2026-11-21. This is a selected subset and profile changes require versioning and review.

## Release boundary

S14's cross-repository wire format remains under review. Before any integration or emission, agree on versioned records, bounded evidence, source locators and registry semantics with HTP; add paired positive and negative receiver/producer fixtures, deploy receiver and truthful H04 display first, and verify exact receipt compatibility. Gate emission off by default until that work and real-host verification complete. Roll back by disabling emission and retaining legacy readers and immutable reports. This module alone does not complete issue #4: complete type and nested-property checks, complete graph-identifier and reference semantics, referenced-resource integration, visible-content mismatch candidates, coverage policy, end-to-end tests, and production verification remain.

The inactive `local_sidecar` adapter prepares the provisional `s04-structured-data` / `s04-local-1` envelope. It maps unavailable source to `unavailable`, incomplete coverage or unknown resource status to `partial`, and complete observations to `observed`; omission counts remain unknown when evidence is incomplete. It performs no checkpoint or collection. The shared job budget, atomic checkpoint integration and run coverage remain pending review.

Saved-report validation accepts schema 1 and schema 2 with evidence contract version 1. It validates retained page records, not contract evaluations or coverage claims; partial or truncated contract summaries do not limit the retained pages examined. It requires an explicit `structured_data` array on each page. Reports missing that collection are rejected because absence cannot establish that extraction observed an empty collection. An invalid page URL produces partial coverage while base-independent checks continue. Unsupported custom context subtrees are not interpreted.

The output limits apply per page; the standalone wrapper has no aggregate report-output cap. Offer currency inside a price specification remains unknown rather than being inferred absent. Breadcrumb item references are resolved only against unique retained local definitions.

## Representative acceptance fixtures

`fixtures/s04/positive.json` and `fixtures/s04/negative.json` are schema-1 saved
reports for the local saved-report entry point. The positive report contains
valid Product, Article, BreadcrumbList and LocalBusiness markup, an image already
present in the retained inventory and two unavailable pages; it produces only
explicit context coverage, resource status and human-review observations. The
negative report separates JSON syntax, vocabulary, provider-eligibility,
local-reference and human-review conditions at precise RFC 6901 item/property
pointers. Both are exercised directly and through the CLI in
`tests/structured_validation.rs`, and can be run manually with
`seosmith --database /tmp/absent.sqlite validate-structured fixtures/s04/positive.json`.
These are local synthetic observations; they are not a production-readiness,
eligibility or rich-result claim.
