# S06 local detector prototype

The experimental `s06_detector` library module supplies the per-page soft-404 collector for local policy-mode checkpoints. Pair comparisons require an explicit peer. The corpus tests exercise both operations through the library. The caller supplies retained bytes, status, content type, completeness and an explicit comparison peer. Labels, case IDs and rationales are never inputs to the analyzer. `s06-local-detector-2` names these local, provisional semantics, not the S14 contract.

A result is a human-review candidate, no candidate under these narrow patterns, or unknown. SHA-256 identifies source bytes and lowercased extracted main text; bounded excerpts, title, H1, approximate body text outside main, and pair similarity provide evidence. Pair results retain both extracted evidence records, and identify which side was unavailable when extraction or eligibility fails. Exact byte equality is independent of the main-text similarity calculation. The comparison is pairwise: no discovery or clustering is implemented. A 0.8 Jaccard threshold on unique alphanumeric main-text tokens is experimental, not calibrated; repeated words and order do not affect it. Explicit SKU markers suppress a near-duplicate candidate to accommodate common product variants, but are not proof of legitimacy and can hide other cases. Exact byte equality yields a candidate only after both sources pass the complete HTTP 200 and available-main gates; identical shells without available main content remain unknown. For non-identical pages, fewer than three distinct main-text tokens on either side makes comparison unknown; this is a similarity-support guard, not a page-quality threshold. Shared chrome is excluded from the similarity score. Template fraction is only a text-length approximation, not a DOM template model.

Soft-404 detection requires a 200 plus matching exact English error title and H1 patterns. A real 404/410 is not a soft-404 candidate; other statuses, missing source, non-HTML, decoding errors, incompleteness, size limits and missing or loading-only main content are unknown for semantic comparisons. This deliberately misses many errors and cannot assess page purpose or rendered content. No word-count minimum determines value. A negative means only that this heuristic found no candidate, not that a page is useful or safe. Human context and H04/H05 remain necessary; candidates are not penalties or spam determinations.

Parsing is capped at 256 KiB input and 32 KiB extracted text; excerpts contain at most 240 characters. The first `main`, `article`, or role-main element is used; pages without one remain unknown. Static descendant text can include hidden text and scripts; extraction does not execute JavaScript, check visibility, determine intent, or handle all encodings perfectly. The source hash and excerpt do not replace retention of source bytes. The caller must provide truthful completeness and status and retain both sources for comparisons. Corpus response metadata is synthetic; corpus agreement is not an accuracy measurement.

No existing contracts, feature gates or deployment change in this slice. S14 semantics and compatible receiver/storage/read surfaces remain prerequisites to any separately reviewed producer integration. Deploy readers first, then gate any future producer; rollback disables new emission while retaining readers for stored evidence. No production readiness, live crawling, rendering or emission is claimed.

The ordinary `seosmith saved-pair` CLI reuses this detector. Saved checkpoints can only establish identical source bytes because main text is not retained, and only when both saved sides were complete HTTP 200 responses with available main content; a non-200 saved side (for example a 404/410 error page) stays unknown. Callers that need full near-duplicate similarity supply retained HTML files explicitly. See `docs/s06/saved-pair.md` for inputs, provenance, bounds and unknowns.

Run `cargo test --locked --test s06_detector`, `cargo test --locked --test s06_saved_pair`, `cargo test --locked --bin seosmith saved_pair` and `python3 -m unittest discover -s tests/s06 -v`.
