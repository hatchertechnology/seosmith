# Local robots checkpoint

Policy CLI crawls retain robots observations only in the local SQLite store. `local_robots_run.evidence` records the origin and source for each policy fetch, including `unavailable` before any page is saved. At most 32 origins of at most 1,024 bytes are retained; `omitted_origins` counts the rest. The record is written transactionally only while the local job is running. It contains no robots body.

Each page checkpoint has a `robots` collector with the source and decisions for Seosmith, Googlebot, Bingbot, GPTBot and OAI-SearchBot, evaluated from the same decoded body as crawler admission. HTTP 404/410 is `not_found`; 401/403 is `http_denied_synthetic`; other status and transport failures are `unavailable`. Synthetic decisions do not claim line provenance. A matched rule or retained raw line over 1,024 bytes is omitted with `matched_provenance_byte_limit`; a raw line over 16,384 bytes is first omitted by the evidence parser with `matched_line_unavailable` (unless the retained rule independently exceeds 1,024 bytes); the actual matcher outcome remains. Parser disagreements and missing source lines retain the existing evidence module's provenance states. Collector and run budget omissions remain explicit. The page checkpoint and evidence are one transaction, serialized with cancellation; origin records are separate transactions and can therefore precede a page checkpoint.

These named decisions are crawl permissions, not conclusions about indexing. Policy page checkpoints also retain bounded HTTP field occurrences and effective indexing evaluations for those bots, separate from HTML occurrences. Missing, blocked, failed, invalid and limited evidence remains unknown where it cannot support a decision. Desired policy is unknown unless independently supplied; this checkpoint supplies none. Existing local stores acquire the additional table on open; old evidence is not rewritten. Standard reports and delivery are unchanged. No additional HTTP requests are made.
