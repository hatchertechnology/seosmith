# Local collector checkpoint proposal (not frozen)

This is a design for coordination, not an implemented interface or wire contract. Do not enable collectors or deliver these records. Base integration on the reviewed and merged durable-mode change, retaining its recovery and delivery isolation.

A local submission atomically records its execution mode and immutable enabled collector IDs and versions with an initialized run record. Standard and pre-existing jobs do not acquire collectors. Generic page sidecars are keyed by job, exact page URL and collector ID. Every enabled collector supplies exactly one version-bound envelope for every checkpointed page: observed, partial, or unavailable, with source identity and omission count or unknown. S04 paths bind to the page's structured-data observations; S02/S03 and graph preserve ordered source occurrences. A missing legacy sidecar is unknown, never an empty successful observation.

One immediate SQLite transaction checks the current job is the matching local-running job and collector set/version, writes the legacy page and all enabled sidecars, and advances applicable run coverage. Duplicate replay must be idempotent only for identical inputs; divergent replay must not overwrite prior evidence silently. An error or cancellation that wins serialization commits no partial page/sidecar set. Finalization is conditional on current local-running state and immutable after completion; cancellation and finalization have one explicitly tested ordering. A completed or cancelled run is not resurrected by replay. Recovery preserves the durable local mode, collector set and non-deliverability; interrupted and uninitialized legacy coverage is unknown.

The shared run record tracks the crawl interval, collector versions, robots state per origin, sitemap discovery and pending sources, frontier/extraction truncation and omitted counts or unknown. Robots failure before any page is a run observation, not a synthetic page. Sitemap documents and origin edges require bounded idempotent replay, including multiple paths. Collector-specific coverage reconciles its candidate population and missing, unavailable, truncated and omitted evidence. A clean legacy report alone cannot establish complete collection.

Candidate limits under discussion: 16 MiB total per job across serialized sidecars, run and sitemap evidence; S02/S03 page payload 64 KiB and robots source 64 KiB; graph and S04 payload at most 1 MiB per page; S04 additionally limits observations to 512 and values to 4 KiB. Count exact compact UTF-8 bytes including envelopes, in deterministic source order, before the transaction. Reserve capacity for bounded coverage/omission records and define a bounded number of collector/source records. If a trustworthy marker cannot fit, fail the local job rather than claim completeness. These limits, sitemap reservation and accounting are not yet agreed or implemented; do not infer capacity for 20,000 pages from a per-page cap.

Before enabling, test mixed collectors, complete and partial coverage, missing/legacy records, limits and deterministic omission, unavailable robots, sitemap failures and replay, crash between each write, rollback, concurrent cancellation/finalization, changed retry payload, recovery and delivery exclusion. Check exact legacy v1/v2 bytes and receipts remain unchanged. Receiver registration, paired fixtures and rollout are separately required for any future emission.
