# S01 observation/evaluation contract v2

Frozen extension v1 for H01 alignment. `schema_version: 2` adds `evidence_contract` to the
unchanged v1 report fields. v1 remains the default; findings and finding keys are
unchanged. `evidence_contract.version` is 1 (the extension's own version).

The extension contains `policy` (immutable canonical JSON string plus SHA-256
signature), `observations`, `evaluations`, and per-rule `coverage`. Observations
refer to original `/pages/N` JSON pointers and URL-based entity IDs, retain explicit
available/unavailable state and unknown reason, and identify their observation time
as a report interval (legacy collection does not record per-fetch wall time).
Evaluations carry rule/validator version, entity identity, eligibility, attempt,
outcome, unknown reason, source locator, actual/expected state+value, confidence,
observation interval, policy signature, and optional unchanged finding key.

S01 does not infer passes from missing findings. Existing findings become failed
rule evaluations with preserved source evidence; missing_title is instrumented
for explicit pass/fail/not-applicable/unknown. Other rules with no finding retain
unknown eligibility/attempt/outcome (`legacy_not_instrumented`) in per-rule
coverage; they are not silently successful. Coverage totals are per observed
entity, and crawl completion does not imply complete evaluation coverage.

Gate: `--evidence-contract-v2` / `SEOSMITH_EVIDENCE_CONTRACT_V2=true`, default false,
set at process startup. It changes newly finalized reports only; stored payloads
and retries retain original bytes/hash. Deploy H01 receiver support and shared
fixture verification before activation. Roll back by disabling the gate; keep v2
receiver support until retained reports and retries have drained. No production
readiness claim follows from local fixtures.

Shared fixtures live in `fixtures/contracts/` (legacy, v2 complete, partial,
and invalid cases), with Rust producer verification and a standalone Node checker
for both repositories. HTP must preserve exact report bytes and distinguish unknown
from pass, unavailable from empty, and crawl from evaluation coverage.

## Normative semantics (extension v1)

`src/contract.rs` defines the wire fields; checked-in compact JSON fixtures are
producer-generated. `fixtures/contracts/rules.json` is the complete ordered rule
manifest for ruleset `2026-11-01.1`; `coverage` has exactly one row per manifest rule.
Unknown versions must be rejected, never interpreted as legacy success.

Identity is `sha256:` plus lowercase hex SHA-256 of UTF-8
`seosmith-entity-v1\n{kind}\n{url}`, where kind is `page` or `resource` from
`Page.is_resource`, and URL is the **exact stored URL string**. No receiver URL
normalization, decoding, query sorting, case conversion or slash removal occurs.
The collector already normalizes discovery URLs; different stored strings remain
different identities. Duplicate identities in one report are invalid. Finding key
remains the existing lowercase hex SHA-256 of `rule + "\n" + url`, without prefix.
An evaluation is unique on `(entity_id, rule)` within the report. Identity is not a
cross-run assertion that content is unchanged.

`source_locator` uses RFC6901 JSON pointers into the original report: observations
point to `/pages/N`, evaluations to their page or matching `/findings/N`.
`actual`/`expected` are tagged objects: `{state:"source",source_locator:...}`,
`{state:"known",value:"..."}` (string literals only in extension v1), or `{state:"unavailable",reason:...}`. Source references
are evidence values, not copies or omitted values: retain the original report to
resolve them. `null`, empty string and unavailable are distinct. Legacy expected
values use reason `legacy_expectation_not_recorded`; no inferred threshold is added.

Every observation/evaluation inherits `observed_at` and `policy.signature` from its
containing extension. `observed_at` is `{started_at,finished_at}` (RFC3339), an
observation interval enclosing the crawl; it is explicitly **not** a per-fetch time.
Unavailable observations use `robots_blocked`, `fetch_failed`, or `not_fetched`.
Available means an HTTP observation exists, not that HTML extraction is complete.

Allowed evaluation state tuples `(eligibility,attempt,outcome)`:

- `(eligible,completed,pass|fail)` with null unknown_reason and confidence `high`.
- `(ineligible,not_attempted,not_applicable)` with null unknown_reason, confidence
  `high`, actual unavailable (`not_html_page`).
- `(unknown,not_attempted,unknown)` with reason `source_unavailable` or
  `extraction_truncated`, confidence `unknown`, actual unavailable.

Unknown uninstrumented or omitted combinations are represented only in coverage,
not one row per entity/rule. Other state tuples are reserved and invalid in v1.
A missing_title pass is an explicit nonempty-title predicate on successful HTML
pages, with intact extraction and no fetch error; it is not the absence of a
finding. Extraction truncation makes missing_title unknown even if a legacy
finding exists. Other observed legacy findings represent completed failures of
that legacy validator, with its original evidence; confidence `high` concerns the
recorded validator outcome, not business impact or exhaustive coverage.

Coverage denominator `entities` is **all stored pages including resources**, not
all discovered URLs, eligible pages, or the unbounded web. Unvisited frontier URLs
are outside this denominator; top-level coverage_complete/stop_reason retain crawl
coverage. Each row has these independently exhaustive sums:

- eligible + ineligible + eligibility_unknown = entities
- attempted + not_attempted + attempt_unknown = entities
- passed + failed + not_applicable + unknown = entities
- sum(unknown_reasons values) = unknown

Each emitted evaluation contributes once. All other entity/rule pairs contribute
unknown eligibility, attempt and outcome with `legacy_not_instrumented`, or
`contract_limit` when omitted by the bounds. No skipped combination is a pass.
`evaluation_coverage_complete` requires crawl coverage_complete, no truncation,
and zero unknown outcomes for every rule. `truncated` means metadata was omitted
by contract limits, independently of crawl or extraction truncation.

Policy canonicalization: build the exact fixed policy object shown in fixtures,
serialize keys in lexicographic order, UTF-8 JSON, no whitespace, normal JSON string
escaping, integers as decimal. No request/run/website ID, binding generation, or
time participates. Seed URL, all crawl limits/options, policy version, engine,
ruleset and validator version do participate. `signature` is `sha256:` plus hash of
**exact canonical_json bytes**, a reproducibility digest, not authentication.
Receivers verify canonical serialization, fields and hash. `comparison_key` equals
this signature; engine/ruleset/validator changes necessarily change comparison
identity. Do not compare policy digests alone as evidence of crawl completeness.
S14 will separately evolve policies; it is not implemented by S01.

## Bounds, failures, deployment and verification

Maximum extension records: 128 observations, 512 evaluations; maximum compact UTF-8
extension size 1,048,576 bytes. The report still has the existing 16,777,216-byte
transport limit (40,000 combined page/resource records, 400,000 findings). Metadata
uses source pointers and bounded scalar strings, with per-rule coverage aggregates;
no page-by-rule evaluation vector is constructed. Records beyond either metadata
limit are unknown with contract_limit. `omitted_observations` equals pages.length
minus observations.length. Coverage includes all observed entities even when their
metadata was omitted. Engine/ruleset strings <=128 bytes, timestamps <=64 bytes,
seed <=16,384 bytes, finding keys exactly 64 hex characters are checked before
metadata construction. The byte budget is measured with a counting serializer
before persistence, without allocating a second report payload. If base+extension
cannot fit the delivery cap, finalization fails; it never silently emits legacy or
a misleading complete result. Operators must reduce crawl limits and resubmit with
a new request ID. Existing delivery payloads are never rewritten on gate changes.

Order: (1) land shared fixtures/receiver validators; (2) verify both repositories,
including exact-byte retries, partial/unknown/truncation handling and rejection
fixtures; (3) deploy H01 and confirm installed receiver capabilities advertise v2;
(4) explicitly enable producer startup gate. This PR does not deploy or enable it.
Rollback producer by disabling gate; keep receiver dual-version support through
retention/retry drain. Rolling back receiver first will reject queued v2 payloads;
retain them for retry, never rehash or downgrade them. No automatic negotiation or
activation is implemented here. A complete crawl fixture still has incomplete
rule coverage, intentionally. Local tests are not production rollout evidence.
