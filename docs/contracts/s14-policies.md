# S14 experimental advisory policies

The default remains legacy behavior. `--advisory-policy PATH` (or `SEOSMITH_ADVISORY_POLICY`) opts in using a JSON object with optional `title_min`, `title_max`, `description_min`, `description_max`, `words_min`, `links_max`, `require_indexable`, and `forbid_redirects`. Defaults match legacy numeric thresholds and do not assert indexing or redirect intent. Thresholds label contextual advisories, not universal SEO requirements. Missing x-default is not a defect. Original page observations remain available; unavailable or truncated extraction does not establish an advisory pass.

The experimental report uses schema 3 with `policy_guidance` catalog version s14-1 and the effective config. Each affected finding is classified as advisory or an explicit policy violation. Other legacy findings retain their legacy semantics; their applicability and source cannot be inferred from this catalog. This is deliberately incompatible with H01's frozen S01 schema 2: S01 currently represents legacy findings as failed evaluations. Combining the flags is rejected until a jointly versioned contract can preserve advisory and observation semantics and comparison identity. Do not send schema 3 to production HTP. H04 must support these semantics and H01 must accept the agreed wire format before activation; tests alone do not establish readiness. Roll back by removing the policy option; stored schema 3 reports require compatible readers for as long as retained. Never rewrite stored report bytes or retry payloads.

The experimental option is accepted only by one-shot `crawl`: output is printed locally and is not persisted or queued for delivery. Its job is marked `local_only` without a stored report to prevent restart requeue; use a new request ID for another run. `serve` rejects the option. This temporary restriction must be replaced with an agreed durable lifecycle before activation.

Local output now includes a generated candidate and manifest for six scalar advisories, explicit noindex/redirect intent, and observations of robots, HTTP status, alternates, and fetched external targets. The canonical policy includes effective options and the crawl request. `validate_generated` regenerates the fixed candidate universe and checks exact equality; it is a producer-side check, not a receiver validator. Per-rule coverage marks omitted, unknown, or incomplete crawls incomplete. External link records use report-local edge ordinals; unavailable targets retain the source link pointer and an unknown outcome, while observed targets also reference their status. Edges never resolve across runs. The bounded candidate can reject large reports when manifest bounds are exceeded. Shared schema-3 acceptance, full interoperability and receiver validation are not implemented; the draft wire proposal remains subject to review.

In opt-in local output, legacy external-link broken/redirect findings and out-of-scope fetch/client/server errors are suppressed in favor of observation and unknown evidence. Legacy sitemap/canonical/hreflang noindex and redirect-target findings are also suppressed because the local policy does not express intent for those relationships. Original pages and links remain evidence. S14 findings use a separate `seosmith-s14-finding-v1` key namespace. The catalog's `alternates_observed` record reports collection count and x-default presence; absence is not a defect. `candidate.observed_at` copies the report start/finish interval. The candidate contract and delivery remain subject to joint review and receiver support.

Schema 3 retains the legacy `ruleset_version` for the retained legacy rules; the independently versioned S14 catalog and validator are identified in the canonical policy. Consumers must not infer S14 semantics from the legacy ruleset version. Cross-run comparisons require independently verified website and binding scope in addition to equal policy and manifest identities.
