# S14 local contract s14-local-1 — frozen for local use

The finite local contract `s14-local-1` comprises the one-shot producer, local JavaScript checker, state matrix and committed vectors reviewed at `448baa3`. It is frozen for local use only. Existing v1/v2 reports and S01 extension v1 remain unchanged. This is not an implemented or frozen receiver delivery contract: H01 continues to reject schema 3 without a receipt until a separately agreed receiver validator and readers are installed.

## Identity and provenance

Entity identity inherits S01 exact URL/kind identity. Record identity is SHA-256 of UTF-8 `seosmith-record-v1\n{category}\n{rule_id}\n{rule_version}\n{entity_id}\n{discriminator}` prefixed `sha256:`. Each component must be nonempty ASCII without control characters, max 256 bytes, with entity ID max 71; discriminator is `self` for scalar page records, or `edge:{ordinal}` where ordinal is the canonical zero-based index in the original page links array. This distinguishes parallel occurrences; identity is stable only for the same original ordered evidence, not an assertion across changing arrays. Duplicate record IDs are invalid. Existing legacy finding keys remain separate and are not mapped to record IDs. Rule IDs, category, discriminator, and pointer must agree with a manifest entry; source pointers start `/pages/{index}` and must resolve to the matching entity and its indexed link when applicable. External edge records include a context locator to that source link; observed targets additionally include a target locator to the matching fetched page status, while unavailable targets have no target locator and remain unknown. Provenance includes a source pointer or unavailable reason, and report observation interval. Policy scope must include that entity; a source belonging to another page is invalid.

## State matrix

`fixtures/policies/state-matrix.json` lists the local contract’s allowed category/state tuples; all unlisted combinations are invalid. Actual values are either `source` (pointer) or `unavailable` (nonempty reason); unknown and not applicable have explicit reasons. Completed observations state facts only; completed advisories indicate threshold crossing but do not assert a defect. Violations require explicit intended policy and eligible scope; unavailable facts yield unknown, never no-violation. Expected policy/threshold is required for completed advisory and violation records, absent for observations. Every record includes provenance; missing values are not converted into empty strings or inferred passes. A manifest defines which category/rule pairs and relationship kinds are applicable, and all fields are closed against unknown keys. Additional tuples require a version change.

## Policy canonicalization and limits

Local policy canonicalization: UTF-8 compact JSON with recursively UTF-8-byte-sorted Unicode object keys (no normalization), no insignificant whitespace; forbid duplicate decoded keys, floating point numbers and strings containing unpaired surrogates. Values are null, booleans, safe integers (-9007199254740991 through 9007199254740991), strings, arrays or objects. Encode non-ASCII including U+2028/U+2029 as UTF-8; escape quote and backslash, use short escapes for backspace, tab, newline, form feed and carriage return, lowercase \u00xx for remaining controls, and do not escape slash. Serialize integers as base-10 without leading zeros or negative zero. Hash exact canonical bytes with SHA-256 and retain both bytes and `sha256:` lowercase hex digest. Canonical policy covers schema, catalog and validator versions, effective defaults, every threshold and intent, intent scope, crawl seed and collection options. Receiver checks these against request and manifest. Local limits: policy 64 KiB, report 16 MiB, depth 64 containers root=1, rule manifest 256 entries and 256 KiB, coverage at most 256 rows (exactly one per manifest row) and 256 KiB, at most 64 reason entries per row with 256-byte reason strings, emitted records 512, observations 128, strings 16 KiB, pointers 1024 bytes. Any receiver use requires separate feasibility review and agreement. No category or rule can disappear silently at a cap.

## Coverage and comparison

Manifest supplies each category/rule pair and candidate population, including explicit zero denominators. Each coverage row totals eligible/ineligible/unknown, attempt counts and outcome counts across the entire candidate population; unknown reasons sum to unknown outcomes. Emitted records reconcile to counts; any omitted records have an explicit count and reason. Counts must not imply identities for omitted records. Missing rows, truncated discovery, omitted relevant evaluations or unknowns make that pair incomplete. A violation can resolve only when the same record identity and policy identity have a complete relevant crawl and completed eligible no-violation evaluation; observation, advisory, missing, unknown and not-applicable never resolve it. Changed policy digest, manifest, identity/validator semantics or incompatible coverage is non-comparable. Edge ordinals are report-local: edge records never resolve across runs, even where ordinals happen to match. Scalar self records resolve only under identical policy, manifest and version identities, complete relevant coverage and explicit eligible no_violation.

## Freeze and rollout

Before a receiver delivery contract is frozen, agree receiver-specific exact-byte, receipt and both-path valid/invalid/oversize/cross-version vectors in addition to the local bundle. Validator must reject duplicate decoded keys, depth 65, invalid identity, scope, policy, tuple, counts, and missing manifest entries without receipt. Advertise capability only after matching validator and readers are installed. Deploy receiver/readers first, verify capability and exact bytes, then H04 display and end-to-end semantics; only after that explicitly enable producer. Disable producer to roll back and retain schema 3 readers while any rows exist. No deployment or activation is authorized.

## Local encoding and receiver considerations

Order object keys by UTF-8 bytes (equivalent to Unicode scalar-value order for valid Unicode), without normalization. JavaScript default UTF-16 sorting and Postgres jsonb rendering are not canonical. Policy integers must be within -9007199254740991..=9007199254740991. Policy string encoding uses UTF-8 for non-ASCII including U+2028/U+2029; escape `"` and `\\`, use `\b`, `\t`, `\n`, `\f`, `\r` for those controls and lowercase `\u00xx` for other U+0000–U+001F; do not escape slash. The committed golden vectors cover supplementary versus BMP keys, canonical-equivalent but byte-distinct combining sequences, escaping, integer boundaries and digest. The independent JavaScript checker is a local contract checker, not a receiver validator.

Edge ordinal IDs are valid only within one report. Reordered or changed relationships invalidate ordinal correspondence; schema 3 never resolves edge violations across runs. Record identity inputs must contain entity hash, not a raw URL. All size limits count UTF-8 bytes. The local byte caps cover total manifest and coverage as well as rows, reasons and strings; do not claim complete coverage from aggregate totals without verifying the manifest candidate universe, scope, residual omitted accounting and unknown-reason reconciliation. The machine matrix specifies `actual`, `expected`, `reason`, confidence and inherited interval/policy fields, including observation ineligibility and source/expected binding. Omitted IDs cannot be assumed. Receiver both-path positive/negative/oversize and cross-version acceptance remain separately open.


## Local state and coverage choices

The machine tuple matrix specifies `actual`, `expected`, `reason`, confidence and inherited interval/policy for every permitted tuple. Observation ineligibility is invalid. Completed advisory and policy-violation expected values must point to the applicable canonical policy; observations and non-completed tuples require null expected. High confidence indicates an observed source, not certainty of an SEO defect; unknown and not-applicable use unknown confidence. Source locators bind to the same entity and edge.

Each manifest row declares its category/rule and candidate universe. Each coverage row has its denominator and exhaustive eligibility, attempt and outcome counts, each summing independently to the denominator. Unknown-reason counts sum to unknown outcomes. Emitted category/state counts reconcile with records; omitted residual equals denominator minus emitted records. Omitted, unknown or truncated means that row is incomplete. Manifest and coverage are each capped at 256 KiB, reason entries at 64 per row and reason strings at 256 UTF-8 bytes.

The conformance bundle must include existing legacy/v2 acceptance, v3 complete and partial/omitted, advisory versus violation, explicit noindex/redirect intent, unavailable external target, reordered edges, changed policy, invalid tuple, missing manifest, duplicate key, depth 65, limit excess and digest vectors. Receiver worker and import must exercise exact bytes and receipts. The local bundle exercises these cases within its stated scope; receiver acceptance and exact-byte receipt behavior remain outside the local freeze.


## H01 source-binding clarifications

An absent x-default is evidenced by the existing enclosing page alternates collection, not a pointer to a nonexistent array element. Claim absence only after complete extraction of that collection; unavailable or truncated extraction yields unknown. The policy_source expected value is an RFC 6901 pointer into the parsed canonical policy string, not the report. It must resolve to the effective threshold or directive applicable to the record's rule and scope; malformed, dangling, wrong-rule or wrong-scope policy pointers are invalid. The local checker verifies binding to the local manifest and effective policy; receiver authorization and binding verification remain separate responsibilities.


Policy comparison identity excludes per-run request ID, website ID and binding generation. Compare only runs within the same independently verified website and binding scope; policy digest covers the seed and effective collection options and must not substitute for this scope check. The `alternates_observed` record refers to the complete observed collection, including an empty collection; it makes no assertion that a missing x-default is a defect.

The producer candidate embeds `observed_at` with the report's `started_at` and `finished_at`; each record's `interval_ref` is `candidate.observed_at`, validated against the report interval. Completed observation records also carry a typed observed fact bound to the original source. `validate_generated` is the producer-side authoritative recomputation entry point; the internal structural check alone is not a receiver conformance validator. Cross-run scope equality must be independently verified by the caller before invoking the local lifecycle predicate; an unverified or different website/binding scope must not be treated as equal. The local schema-3 format remains unapproved for delivery.

## Local comparison identity candidate

Scope identity uses `seosmith-scope-v1\n` plus ordered tagged UTF-8 fields `website_id` and `binding_generation`; each field is encoded `name=byte_length:value\n`. Manifest identity uses `seosmith-manifest-v1\n`, `rows=N\n`, then the tagged fields `category`, `rule_id`, `rule_version`, `expected_type` and `expected` for rows sorted by category/rule/version, and `end\n`. `expected_type` is `null` or `pointer`; null has empty expected value. Candidate populations are excluded from manifest identity but independently checked per report. Both use lowercase `sha256:` hex. A rebind changes scope identity. Local scope identity is not authorization; a receiver must verify the authenticated binding to the website.

The local comparison function validates both reports, checks the records are actual members, and derives policy, scope and manifest equality plus current crawl and per-rule coverage completeness from those reports. Missing data and edge ordinals fail closed. `scripts/test-s14.mjs` runs the independent JavaScript checker and committed local vectors; this is not a deployed receiver.

For the local byte checker, `coverage_complete` and `check_external_links` are JSON booleans; request budgets and page counts/status are nonnegative safe integers (HTTP status additionally fits u16). Page and link URLs must be absolute HTTP(S), and the seed must equal its URL-parser canonical serialization, with no credentials, explicit port, query, or fragment. Request and website UUIDs use canonical lowercase form. Self records have no context or target locator. Unknown-reason entries have positive integer counts; omit zero-count reasons. The Rust lifecycle requires both reports to be schema 3. These local requirements do not authorize delivery of schema 3.

## Numeric-token interoperability boundary

Canonical policy bytes use the lexical integer grammar above and are checked byte-for-byte. For numeric fields elsewhere in a report, the Node checker checks the parsed value as a safe integer, rather than enforcing a lexical integer token. It may therefore accept `200.0` or `200e0` as the same integral value as `200`, while Rust typed deserialization may reject those raw spellings. This local freeze is value-semantic for those Node checks and does not claim raw lexical parity with Rust or receiver acceptance.

## Production emission (schema 4)

With `--policy-wire-v1` (`SEOSMITH_POLICY_WIRE_V1=true`, default off; requires `--advisory-policy`, refused together with `SEOSMITH_EVIDENCE_CONTRACT_V2`) the worker emits `s14-wire-1` schema-4 reports with S01 evidence v1 and `finding_coverage`, and delivers them to the policy route (`HTP_INGEST_URL`).

- `finding_coverage_prototype::generate_wire_v1` is the production serialiser, in this order: `audit::analyze`; `policy::apply_with_evidence` (findings are now final); policy validation and edge reconciliation; `contract::attach_v1_schema4` over the final findings; canonical policy; `schema_version = 4`; the byte caps; the equality check against the pinned population; `finding_coverage`; the last serialisation. `generate` is the evidence-free fixture form and is unchanged.
- The returned bytes are stored by `Store::finish_bytes` and delivered byte for byte. `Store::finish` still handles schema 1/2 only and refuses schema 4.
- Any generation, cap, equality or evidence error fails the job (`state = failed`, nothing delivered) inside `finalize_job`; the worker continues with the next job. The remedy for an oversize report is a lower `max_pages`.
- On the `/policy-audits` route (decided by the path suffix of `HTP_INGEST_URL`), HTP `422` and `409` are terminal (`delivery_state = rejected`, `error = htp_semantic_mismatch` / `htp_delivery_conflict`). `400`, `5xx`, `429` and `503` retry as before. The legacy `/audits` route keeps retrying `422`/`409`: its `Json` extractor can return 422.
- `crawl --request <file> --policy-wire-v1 --advisory-policy <file>` prints the exact wire bytes and delivers nothing. The advisory policy used in production is `fixtures/policies/production-default.json` (`{}`).
- The test-only `local-e2e` Cargo feature lets `serve` use plain HTTP to `127.0.0.1` or `::1` only. It does not compile without debug assertions.
