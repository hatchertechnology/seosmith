# S14 schema 3 candidate — not frozen

This is a coordination proposal, not an implemented delivery contract. Existing v1/v2 reports and S01 extension v1 stay unchanged. H01 must reject schema 3 without receipt until validator and readers are installed. PR22's local prototype is not this contract. Jointly freeze this document, machine-readable tuple matrix and vectors before any producer/receiver delivery implementation.

## Identity and provenance

Entity identity inherits S01 exact URL/kind identity. Record identity is SHA-256 of UTF-8 `seosmith-record-v1\n{category}\n{rule_id}\n{rule_version}\n{entity_id}\n{discriminator}` prefixed `sha256:`. Each component must be nonempty ASCII without control characters, max 256 bytes, with entity ID max 71; discriminator is `self` for scalar page records, or `edge:{ordinal}` where ordinal is canonical zero-based index in the original page relationship array. This distinguishes parallel occurrences; identity is stable only for the same original ordered evidence, not an assertion across changing arrays. Duplicate record IDs are invalid. Existing legacy finding keys remain separate and are not mapped to record IDs. Rule IDs, category, discriminator, and pointer must agree with a manifest entry; source pointers start `/pages/{index}` and must resolve to the matching entity and its indexed relationship when applicable. Provenance includes a source pointer or unavailable reason, and report observation interval. Policy scope must include that entity; a source belonging to another page is invalid.

## State matrix

`fixtures/policies/state-matrix.json` lists all proposed allowed category/state tuples; all unlisted combinations are invalid. Actual values are either `source` (pointer) or `unavailable` (nonempty reason); unknown and not applicable have explicit reasons. Completed observations state facts only; completed advisories indicate threshold crossing but do not assert a defect. Violations require explicit intended policy and eligible scope; unavailable facts yield unknown, never no-violation. Expected policy/threshold is required for completed advisory and violation records, absent for observations. Every record includes provenance; missing values are not converted into empty strings or inferred passes. A manifest defines which category/rule pairs and relationship kinds are applicable, and all fields are closed against unknown keys. Additional tuples require a version change.

## Policy canonicalization and limits

Candidate canonicalization: UTF-8 compact JSON with recursively UTF-8-byte-sorted Unicode object keys (no normalization), no insignificant whitespace; forbid duplicate decoded keys, floating point numbers and strings containing unpaired surrogates. Values are null, booleans, safe integers (-9007199254740991 through 9007199254740991), strings, arrays or objects. Encode non-ASCII including U+2028/U+2029 as UTF-8; escape quote and backslash, use short escapes for backspace, tab, newline, form feed and carriage return, lowercase \u00xx for remaining controls, and do not escape slash. Serialize integers as base-10 without leading zeros or negative zero. Hash exact canonical bytes with SHA-256 and retain both bytes and `sha256:` lowercase hex digest. Canonical policy covers schema, catalog and validator versions, effective defaults, every threshold and intent, intent scope, crawl seed and collection options. Receiver checks these against request and manifest. Proposed limits: policy 64 KiB, report 16 MiB, depth 64 containers root=1, rule manifest 256 entries and 256 KiB, coverage 768 rows and 256 KiB, at most 64 reason entries per row with 256-byte reason strings, emitted records 512, observations 128, strings 16 KiB, pointers 1024 bytes. Limits are candidates requiring cross-language vectors and receiver feasibility review. No category or rule can disappear silently at a cap.

## Coverage and comparison

Manifest supplies each category/rule pair and candidate population, including explicit zero denominators. Each coverage row totals eligible/ineligible/unknown, attempt counts and outcome counts across the entire candidate population; unknown reasons sum to unknown outcomes. Emitted records reconcile to counts; any omitted records have an explicit count and reason. Counts must not imply identities for omitted records. Missing rows, truncated discovery, omitted relevant evaluations or unknowns make that pair incomplete. A violation can resolve only when the same record identity and policy identity have a complete relevant crawl and completed eligible no-violation evaluation; observation, advisory, missing, unknown and not-applicable never resolve it. Changed policy digest, manifest, identity/validator semantics or incompatible coverage is non-comparable. Edge ordinals are report-local: edge records never resolve across runs, even where ordinals happen to match. Scalar self records resolve only under identical policy, manifest and version identities, complete relevant coverage and explicit eligible no_violation.

## Freeze and rollout

Before freeze publish canonical bytes/digest and record/pointer test vectors, manifest, exhaustive tuple/required field matrix, counts/omission examples and both-path valid/invalid/oversize/cross-version vectors. Validator must reject duplicate decoded keys, depth 65, invalid identity, scope, policy, tuple, counts, and missing manifest entries without receipt. Advertise capability only after matching validator and readers are installed. Deploy receiver/readers first, verify capability and exact bytes, then H04 display and end-to-end semantics; only after that explicitly enable producer. Disable producer to roll back and retain schema 3 readers while any rows exist. No deployment or activation is authorized.

## Receiver review corrections — still not frozen

Order object keys by UTF-8 bytes (equivalent to Unicode scalar-value order for valid Unicode), without normalization. JavaScript default UTF-16 sorting and Postgres jsonb rendering are not canonical. Candidate integers must be within -9007199254740991..=9007199254740991. Proposed string encoding uses UTF-8 for non-ASCII including U+2028/U+2029; escape `"` and `\\`, use `\b`, `\t`, `\n`, `\f`, `\r` for those controls and lowercase `\u00xx` for other U+0000–U+001F; do not escape slash. Golden vectors must cover supplementary versus BMP keys, canonical-equivalent but byte-distinct combining sequences, escaping, integer boundaries and digest. The current local candidate validator is incomplete and is not a conformance or receiver validator.

Edge ordinal IDs are valid only within one report. Reordered or changed relationships invalidate ordinal correspondence; schema 3 never resolves edge violations across runs. Record identity inputs must contain entity hash, not a raw URL. All size limits count UTF-8 bytes. Freeze byte caps for total manifest and coverage as well as rows, reasons and strings; do not claim complete coverage from aggregate totals without verifying the manifest candidate universe, scope, residual omitted accounting and unknown-reason reconciliation. The machine matrix must explicitly specify `actual`, `expected`, `reason`, confidence and inherited interval/policy fields, including observation ineligibility and source/expected binding, before it can be frozen. Omitted IDs cannot be assumed. These and both-path negative/oversize, cross-run reorder and changed-policy fixtures remain open with t18.


## Candidate freeze choices from H01 review

The machine tuple matrix specifies `actual`, `expected`, `reason`, confidence and inherited interval/policy for every permitted tuple. Observation ineligibility is invalid. Completed advisory and policy-violation expected values must point to the applicable canonical policy; observations and non-completed tuples require null expected. High confidence indicates an observed source, not certainty of an SEO defect; unknown and not-applicable use unknown confidence. Source locators bind to the same entity and edge.

Each manifest row declares its category/rule and candidate universe. Each coverage row has its denominator and exhaustive eligibility, attempt and outcome counts, each summing independently to the denominator. Unknown-reason counts sum to unknown outcomes. Emitted category/state counts reconcile with records; omitted residual equals denominator minus emitted records. Omitted, unknown or truncated means that row is incomplete. Manifest and coverage are each capped at 256 KiB, reason entries at 64 per row and reason strings at 256 UTF-8 bytes.

The conformance bundle must include existing legacy/v2 acceptance, v3 complete and partial/omitted, advisory versus violation, explicit noindex/redirect intent, unavailable external target, reordered edges, changed policy, invalid tuple, missing manifest, duplicate key, depth 65, limit excess and digest vectors. Receiver worker and import must exercise exact bytes and receipts. These candidate choices await implementation and cross-implementation review before freeze; the local validator does not implement all of them.


## H01 source-binding clarifications

An absent x-default is evidenced by the existing enclosing page alternates collection, not a pointer to a nonexistent array element. Claim absence only after complete extraction of that collection; unavailable or truncated extraction yields unknown. The policy_source expected value is an RFC 6901 pointer into the parsed canonical policy string, not the report. It must resolve to the effective threshold or directive applicable to the record's rule and scope; malformed, dangling, wrong-rule or wrong-scope policy pointers are invalid. Full scope binding requires the frozen manifest and is not yet implemented by the local candidate validator.
