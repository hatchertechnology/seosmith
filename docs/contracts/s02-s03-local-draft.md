# S02/S03 collection draft (local only; not frozen)

`fixtures/s02-s03/local-collection-v1.json` is an illustrative draft, not a wire contract or validated producer output. A new independently versioned wire extension, registry and receiver vectors must be agreed before emission. Existing v1/v2 and local schema 3 stay unchanged. Missing sidecars on old or resumed jobs are unavailable, never empty evidence. Collection interval is the enclosing crawl interval, not a fabricated fetch timestamp.

Occurrences bind to the containing exact page URL or sitemap URL. `ordinal` is zero-based within the same source on that page, in input order, including malformed occurrences. For HTTP, retain each UTF-8 header field occurrence and its HTTP-library iteration position before interpreting agent scopes or directives; a non-UTF-8 relevant field makes HTTP capture unavailable; parsed bot/value alone cannot reconstruct bytes. HTML occurrence retains DOM-decoded attribute values (not original HTML bytes) and whether it appeared in head or body, together with document-order index (DOM reparenting and byte offsets are not claimed). HTTP Link and HTML canonical observations are separate; raw missing, empty, invalid and valid values are distinct. Alternate occurrences retain raw rel, hreflang and href attributes, parsed target or error, and position. Parsing never turns uncollected evidence into an empty successful collection.

Sitemap documents retain their URL, initiating sitemap URL or robots/default discovery source, status, fetch and parse state, and raw entry occurrences in order. Entries retain raw loc and lastmod, explicit missing/empty/invalid/valid states, and resolved scope status. Multiple origins for the same target are independent entries. A valid lastmod needs a defined date grammar; `present` alone does not imply validity. Parse failures and limits make collection incomplete, including when a prefix of entries is available.

Candidate limits: 2,000 occurrences per category per page, 16,384 UTF-8 bytes per raw value, and bounded document/body and sitemap limits inherited from the fetcher. Track every omitted occurrence if count is known, otherwise an explicit unknown omission count; never silently truncate or report complete. Bounds and exact representations remain subject to cross-owner review. Total storage and collection budgets must be specified before implementation is enabled. Capture mode must be durable from submission through recovery; sidecar and page checkpoint must commit atomically. Local collection is not an authorization for incompatible delivery.

## Run-level coverage proposal (not frozen)

A shared local-only run record should be initialized atomically with durable execution mode, before crawling. Suggested fields: `version`, request ID, enabled collectors and versions, state (`uncollected`, `collecting`, `complete`, `partial`, `failed`), and an interval from the job's recorded start/finish. Independently record robots fetch state per origin, sitemap discovery state (including timeout/limit and pending sources), frontier/discovery and extraction truncation, and per-collector omitted counts or explicit unknown when not countable. A `complete` state requires evidence that the relevant source and all required checkpoints were collected; it cannot be derived from a clean legacy report or an empty sidecar. Robots unavailable before the first page must be represented here, not by a fabricated page. Interruptions and old local checkpoints with no initialized run record remain unknown.

Use one transaction for a page and all enabled collectors' sidecars, and initialize/update run coverage without enabling delivery. Recovery mode, collector selection and their versions must persist before any writes. Sitemap documents and their origin edges need idempotent replay/checkpoints, including multiple index paths; timeout, malformed input, blocked fetch and caps make the relevant discovery coverage partial. Shared graph collector needs the same run-level state. Exact table, transaction and recovery semantics require review with the graph and durable-mode owners.

The local collector now bounds each HTTP and HTML occurrence list to a deterministic prefix of approximately 28 KiB of compact serialized records, as well as 2,000 entries and 16,384 bytes per value. It records the number omitted and marks that source incomplete. `enforce_page_budget` further reduces a page sidecar against a caller-provided compact UTF-8 byte budget, preserves occurrence prefixes, marks omissions, and removes robots rule provenance with `budget_omitted` when needed; it fails if the minimum marker cannot fit. It is not yet called by the checkpoint path. These local caps do not replace the proposed shared per-job budget and reserved run-level coverage space. Integration must account for all collectors and sitemap metadata atomically and test overflow/recovery before exposure.

For the local example, ordinals are zero-based per source within a page or document; malformed and empty occurrences consume an ordinal. DOM `document_order` is separate, and gaps are permitted when bounded capture omits occurrences. The JSON example is illustrative and does not yet encode every field of the implemented `PageCapture`; it must not be used as a receiver acceptance vector.

`enforce_document_budget` bounds a sitemap document's compact JSON, preserving a prefix and marking `budget_limit`; it does not include any outer checkpoint envelope. Integration must reserve envelope and shared coverage space before choosing its budget. Parsed-document failures or entry caps leave `omitted_entries` unknown; a clean document reduced by the helper has an exact dropped-entry count. This helper is not wired to persistence.
