# Local page checkpoint (experimental)

A policy-mode CLI crawl uses the same crawler as standard mode, but atomically saves each frontier page with a local evidence record. The record is keyed by the exact request ID and frontier URL; its capture repeats that URL and contains the fixed, version 1 collectors `html_occurrences`, `graph`, and `resource`. Each has `observed`, `partial`, or `unavailable` state and an explanation for partial or unavailable data. HTML decoding errors and graph extraction limits, including truncated link names, are partial. Robots-blocked or failed responses and non-HTML responses are unavailable for the affected collectors. Resource bytes are decoded response bytes, not measured transfer bytes. HTTP occurrence provenance is unavailable because transport has already combined headers. Robots provenance, sitemap evidence and the S06 detector are not integrated. This is not an S02/S03/S05/S06/S08 completion claim or a delivery schema.

Each serialized collector is capped at 24 KiB; an oversized collector is replaced with an explicit unavailable marker. After 16 MiB of run evidence, further pages receive run-limit markers. The existing request limits allow at most 40,000 fetched pages and resources; the exact URL remains the SQLite row key. When its UTF-8 representation exceeds 8 KiB, the redundant URL copy in the capture is omitted with an explicit reason and SHA-256 digest. Page storage itself remains governed by existing crawler limits. The input hash records the bounded capture used for replay comparison, including when the stored capture was replaced by a run-limit marker. It does not assert the identity of data omitted by a collector. No retention or pruning policy is introduced.

The checkpoint requires the exact claimed local request and a local-running job and existing frontier URL. The transaction checks page and capture identity, rejects different replays, and commits page and evidence together. Cancellation or finalization before the transaction rejects the write; if the transaction commits first, cancellation retains that checkpoint. Recovery retains local checkpoints and quarantines interrupted local runs as local-only; it does not resume them. Existing pages without records remain missing evidence, not empty evidence. Existing reports and outbox bytes are not rewritten, and local records are never queued for delivery. This local database format is not registered as a wire producer contract.

## Offline CLI acceptance fixture

A build explicitly compiled with `--features local-cli-fixtures` accepts `SEOSMITH_LOCAL_FIXTURES` for a policy-mode local CLI crawl. The variable names a JSON object mapping exact URLs to `{ "status": 200, "headers": {"content-type": "text/html"}, "body": "..." }` responses. This test-only transport reads at most 1 MiB from the fixture file and never falls back to networking for a missing URL. The feature is disabled in default builds; it does not change the standard crawler or its address checks.

`tests/local_cli_fixture.rs` starts that CLI as a separate process with a synthetic robots file, sitemap response and HTML, then opens the upgraded store. It checks page and collector records, local-only finalization, legacy report bytes, stored hashes, delivery states and the pending queue. No hosted service is needed.
