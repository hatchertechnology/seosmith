# Local page checkpoint (experimental)

A policy-mode CLI crawl uses the same crawler as standard mode, but atomically saves each frontier page with a local evidence record. The record is keyed by the exact request ID and frontier URL; its capture normally repeats that URL and contains version 1 collectors for HTML occurrences, the link graph and resources. Current crawls also record robots provenance, HTTP occurrences and effective indexing decisions. Each has `observed`, `partial`, or `unavailable` state and an explanation for partial or unavailable data. HTML decoding errors and graph extraction limits, including truncated link names, are partial. Robots-blocked or failed responses and non-HTML responses are unavailable for the affected collectors. Resource bytes are decoded response bytes, not measured transfer bytes. The HTTP collector retains bounded occurrences before ordinary headers are combined. Earlier records can lack these collectors. Sitemap evidence and the S06 detector remain outside the checkpoint. See [local robots and indexing evidence](../local-robots-checkpoint.md). This is not an S02/S03/S05/S06/S08 completion claim or a delivery schema.

Each serialized collector is capped at 24 KiB; an oversized collector is replaced with an explicit unavailable marker. The 16 MiB observation threshold is not a hard storage cap: subsequent pages receive constant-size run-limit markers, which also consume space. A transactionally maintained per-run counter tracks evidence bytes; an older database initializes the counter from its existing records once, without rewriting them. Marker rows omit the redundant URL copy and retain its digest; the full URL remains the row key. The existing request limits allow at most 40,000 fetched pages and resources; the exact URL remains the SQLite row key. When its UTF-8 representation exceeds 8 KiB, the redundant URL copy in the capture is omitted with an explicit reason and SHA-256 digest. Page storage itself remains governed by existing crawler limits. The input hash records the bounded capture used for replay comparison, including when the stored capture was replaced by a run-limit marker. It does not assert the identity of data omitted by a collector. Existing local evidence and counters are retained indefinitely; no automatic retention or pruning policy is introduced. The budget covers evidence JSON bytes only, not URLs, pages, SQLite indexes, temporary memory or database overhead.

The checkpoint requires the exact claimed local request and a local-running job and existing frontier URL. The transaction checks page and capture identity and, on first write, matches page depth, sitemap membership and resource classification to the frontier. It rejects different replays and commits page, evidence and byte accounting together. Cancellation or finalization before the transaction rejects the write; if the transaction commits first, cancellation retains that checkpoint. Recovery retains local checkpoints and quarantines interrupted local runs as local-only; it does not resume them. Existing pages without records remain missing evidence, not empty evidence. Existing reports and outbox bytes are not rewritten, and local records are never queued for delivery. A cancellation or other state transition that wins before local finalization makes finalization return an error instead of reporting success. This local database format is not registered as a wire producer contract.

The HTML occurrence extractor may produce a partial result larger than the checkpoint's 24 KiB per-collector cap; in that case the entire collector is explicitly unavailable rather than retaining a prefix with revised omission counts. Replay compares the original bounded capture hash and page bytes, including for run-limit markers, but does not audit database corruption by recomputing hashes of retained captures. These are experimental local storage limits, not assurances about omitted source data.

## Offline CLI acceptance fixture

A build explicitly compiled with `--features local-cli-fixtures` accepts `SEOSMITH_LOCAL_FIXTURES` for a policy-mode local CLI crawl. The variable names a JSON object mapping exact URLs to `{ "status": 200, "headers": {"content-type": "text/html"}, "body": "..." }` responses. For repeated fields, supply `header_fields` as a list of name/value pairs, including the content type. When present, this list supplies all headers and takes precedence over the map. This test-only transport reads at most 1 MiB from the fixture file and never falls back to networking for a missing URL. The feature is disabled in default builds; it does not change the standard crawler or its address checks.

`tests/local_cli_fixture.rs` starts that CLI as a separate process with a synthetic robots file, sitemap response and HTML, then opens the upgraded store. It checks page and collector records, local-only finalization, legacy report bytes, stored hashes, delivery states and the pending queue. No hosted service is needed.

The local `soft_404` collector uses the versioned S06 per-page detector on the fetched response bytes, status and content type. Its candidate is a signal, not a provider indexing determination; unknown and unavailable sources remain explicit. No peer comparison or additional requests are made. Collector and run byte limits apply as for other local evidence; old captures are not rewritten.
