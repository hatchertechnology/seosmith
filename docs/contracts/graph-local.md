# Graph, content and resource evidence: experimental local interface

`graph-local-1` is a research interface, not a report schema or delivery contract. The proposed `crawl_with_local_evidence` collection path is fail-closed until a durable local job mode exists; its dormant implementation stores per-URL JSON separately from the report and checkpoints it with the page in one transaction. The normal crawler does not collect it. `Store::local_graph_evidence` returns records in URL order and marks checkpoints without a sidecar `not_collected`. There is no CLI or API activation and no change to report serialization. The interface is provisional and may change; do not deliver these objects to HTP. A durable local job mode, recovery, cancellation/finalization race protection and coordinated multi-sidecar transaction are prerequisites to exposing the path to users.

HTML observations preserve ordered link occurrences, raw href, resolved URL including fragment, fragment-free fetch URL, a limited accessible-name approximation, element, context and rel-based followability. Fragment checks report missing targets and encoded fragments as unknown; extraction caps prevent a negative claim on truncated collections. Navigation distance derives from observed link edges, not frontier discovery depth; unreachable results on incomplete crawls are unknown. The current graph does not yet account for page-level nofollow or all accessibility naming rules.

Content signals include an exact normalized main-text hash, bounded token fingerprint and excerpt, body/main word counts, title, headings and review-only error signals. Main/article is preferred; fallback to body is not a semantic main-content guarantee. Similarity is a bounded-token Jaccard signal, not a finding, penalty or determination of intent. Empty app shells and error-like titles are review signals, not proof of a soft 404. This prototype does not yet implement clusters or reliable template classification.

Resource observations report decoded body length, declared content length when present, and unavailable transfer bytes separately. The HTTP client may transparently decompress and strip encoding/length headers. Cache and validator headers are observed only when retained by the client. Content hashes apply to returned decoded bytes. PNG/GIF dimensions and PNG/GIF/JPEG/WebP signatures are recognized; absent metadata is unknown. A static dependency graph maps resource relationships including CSS to observed pages; it is not a browser waterfall, rendered image size or actual LCP element. Responsive candidates, loading hints, full format/dimension coverage, byte aggregates and duplicate groups remain open.

Extraction per sidecar is capped at 1 MiB; overflow records an unavailable reason. Crawl limits and missing, blocked, failed, non-HTML and previously collected checkpoints must be interpreted as incomplete, not passes. Remaining work includes bounded total export, explicit per-check coverage, full evidence and fixtures for issue acceptance, durable opt-in mode and failure recovery, receiver-supported versioning, and end-to-end validation. Deploy compatible receivers and readers first; only then explicitly enable a separately agreed producer contract. Roll back by disabling that producer; legacy report behavior remains independent. No production rollout is implied by local fixtures.
