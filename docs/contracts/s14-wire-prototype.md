# S14 wire producer prototype (not frozen)

The `policy-wire-prototype` Cargo feature exposes a local fixture generator for provisional `s14-wire-1`. It does not add a CLI, API, delivery queue, capability advertisement, or production activation. The ordinary store refuses schemas other than 1 and 2; local schema 3 remains one-shot-only. Use the proposed fixture manifest and ingestion cases only for coordinated receiver testing.

The wire policy binds the effective request timing, engine and ruleset in addition to the local policy fields. The prototype preserves local schema-3 generation and separately recomputes external-link wire records and aggregate counts from original source and target observations. A source must be successfully fetched HTML without error, robots block or truncated extraction; otherwise its edge is unknown with `source_unavailable`. A target with missing status, error or robots block is unknown; a recorded target HTTP status is an observation, not a judgment of target health. Ambiguous external target URLs are rejected. Omitted identities are not inferred.

The generator checks the exact receiver byte cap, extension cap and the existing local candidate bounds. It is not an independent untrusted-input validator, and its successful output is not proof of receiver acceptance. It does not implement capability discovery, persisted mode/configuration, durable schema-4 finalization, immutable retry, or the HTP display gate. Receiver raw lexical/duplicate/depth, semantic, authorization and both-path tests must pass before a contract can be frozen. Local candidate generation currently has source-array scanning costs that need representative performance testing.

No production emission is authorized by this prototype. A later gated delivery implementation must keep v1/v2 and local schema 3 unchanged, verify receiver capability and display readiness, persist selection before scheduling, retain exact finalized bytes on retries, and stop new generation first on rollback. Keep compatible receiver readers while any delivered wire reports or queued bytes exist.

The proposed embedded canonical-policy preflight limit is 65,536 UTF-8 bytes inclusive and 64 object/array containers counting the root as one. The typed generator builds a fixed shallow object and checks its byte length; receiver code must bound untrusted embedded JSON before recursive parsing or canonicalization. The separately labeled `policy-raw-*` fixtures test scanner limits only: their objects deliberately do not satisfy the closed policy schema, so scanner acceptance does not mean report acceptance. Native database and API performance remain unverified.
